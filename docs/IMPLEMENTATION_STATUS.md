## 尚未達成的產品／驗收 gate

1. **正式資料服務**：目前只有本機唯讀 FastAPI，尚無資料庫、版本化匯入／staging／發布工作流、角色權限或非同步工作 API。前端 API 失效時會退回歷史彙總／班表 JSON；原始 Excel 僅在本機，已加入 `.gitignore`。
2. **真實供給與即時服務**：TDX OAuth 與靜態官方路線／站序／線形已驗收，但仍可能限流，現有快取提供降級。沒有站點與票證計費站對照、車輛 GPS、ETA 或餘位串接；道路成本圖仍是示意圖。MapTiler 底圖已於本機瀏覽器驗收；production Allowed Origins、用量設定和其他瀏覽器仍待驗收。
3. **可執行旅客規劃**：最低票價演算法只搜尋合成 fixture，未接現行票價／票種、日期有效班表、實體 stop、步行圖、無障礙與餘位。道路最低營運成本 Dijkstra 已在 API 建立，但只用合成路網；仍缺經核對的道路 geometry、轉向／車高限制、即時封路與客運服務成本資料。
4. **完整營運最佳化**：現況是有限候選集窮舉，未實作 CP-SAT 車輛流、driver duty、service-window、容量區段、求解 timeout/bound/gap、同一模擬器回放與 operational-ready 閘門。不能用於實際排班。
5. **孿生驗證**：目前有固定步進與部分守恆測試，尚未覆蓋規格列出的隨機 cohort、取消、故障、保留座位、跨午夜和事件 digest 全套 properties；也未用真實 GPS／班表校準。
6. **行為與觀光分析**：頻次圖是年度卡號出現次數代理值；新增的回程間隔以同卡、同日、反向計費站 OD、12 小時內配對，採非重疊配對並以 k=10 抑制小格。計費站不等於實際上下車站，且跨卡號旅次無法辨識，因此不得稱為完整回程旅次或乘客數。觀光頁可做同路線、同日別標記的往返時間配對，但尚未核對營運日期、景點開放時間、跨路線轉乘、步行、票價、預約座位或回程擁擠風險。
7. **現場與上線驗收**：未做登入與權限、production 部署、正式域名 key 限制、跨瀏覽器／低速網路／WebGL 故障、完整 E2E A/B/C 或業者抽樣驗證。

## 主要外部依賴

- TDX Client ID／Secret：本機後端 OAuth 驗證已通過；憑證僅留在本機 `.env.local`。部署前應透過安全環境變數管理，並避免提交或回顯。
- 真實道路／公車 geometry 與站點對照：需 TDX／政府授權 feed 或業者核對資料。沒有 shape 前不應把示意線當導航。
- 可靠營運成本最佳化：需業者提供有效班表、可用車與車型容量、車輛周轉／空駛規則、駕駛勤務政策、成本 profile 與服務底線。
- 載客率／拒載驗證：需要按區段的車載計數或能校準方向、車次、有效容量的來源；刷卡資料本身不足以判斷滿載與拒載。

## 建議下一個開發 gate

先完成 TDX 後端 adapter 的無憑證降級與 mock contract、再完成可版本化的 GTFS／TDX 匯入與 route/stop mapping。待有效 TDX key 可唯讀取樣、operator 校核樣本後，才讓 GIS 從示意拓樸切換至真實線形；之後以業者提供的班表／車隊／成本建立 CP-SAT oracle 與 simulation verification。詳細順序見 [07_IMPLEMENTATION.md](spec/07_IMPLEMENTATION.md)。
