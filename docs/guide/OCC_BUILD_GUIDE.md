# 日月潭 6670 智慧行控中心：從 API 到儀表板的建置說明

> 對象：要接手、改版或重做這套行控畫面的人。
> 範圍：`occ_dashboard.html`（2D/3D GIS 行控中心）、`3d_viewer.html`（3D 地形沙盤）、`index.html`（入口）。
> 撰寫日：2026-10-25。文中的數字與欄位都在當天實測過。

---

## 0. 整體架構

```
 ┌───────────── 資料來源 ─────────────┐
 │ TDX 官方 API（金鑰）                │  即時車輛位置 A1、所在站 A2、預估到站 N1
 │ 台灣好行官網 Bustime（公開）         │  站牌、路線線形、子線清單
 └───────────────┬───────────────────┘
                 │ 抓下來存成 JSON
                 ▼
        6670_bus_data/*.json  ──────────────┐
                 │                          │
   ┌─────────────┼─────────────┐            │ Blender Python
   ▼             ▼             ▼            ▼
 route_coords.js  occ_dashboard.html 內嵌   render_real_geo_corridor.py
 （路線幾何）     RAW_BUSES / RAW_STOPS …   → 6670_sunmoonlake_panorama.glb
   │             │                          │
   └──── MapLibre GL 地圖 ◄────┘             └──► model-viewer（3d_viewer.html）
                 │
                 ▼
     行控中心畫面（地圖＋車隊＋ETA＋指標）
```

三個原則貫穿全部設計：

1. **資料是什麼就標什麼**：快照標「資料時間」、推估標「推估」、沒有來源的數字標「示意」。
2. **地圖上的車必須在路上**：GPS 先貼合到路線，貼不上的不移動。
3. **同一個畫面只回答調度員的三個問題**：車在哪、快不快、下一站幾分鐘到。

## 1. 怎麼抓 API

### 1.1 兩個來源，各自負責什麼

| 來源 | 需要金鑰 | 提供 | 本專案檔案 |
|---|---|---|---|
| **TDX 運輸資料流通服務平臺** | 要（免費註冊） | 即時位置 A1、所在站 A2、預估到站 N1、班表 | `6670_realtime_bus_positions.json`、`6670_realtime_arrival.json` |
| **台灣好行官網 Bustime**（`taiwantrip.tad.gov.tw`） | 不用 | 站牌清單與座標、路線線形、子線清單；也有 TDX 代理端點 | `6670_all_stops.json`、`6670_linestring.json`、`6670_subroutes.json`、`6670_全線站牌明細.csv` |

**為什麼兩個都用**：TDX 的即時資料欄位標準、有官方維護；好行官網的站牌座標與線形比較貼近官網路線圖，而且有站牌照片、站序等觀光用欄位。

### 1.2 TDX：取得 token

1. 到 https://tdx.transportdata.tw/ 註冊，在會員中心取得 `Client Id` 與 `Client Secret`。
2. 存到 `.env.local`（已在 `.gitignore`），變數名稱見 `.env.example`：`TDX_CLIENT_ID`、`TDX_CLIENT_SECRET`。**不可加 `VITE_` 前綴**，否則會被打包進前端。
3. 換 token（有效期約一天）：

```bash
curl -s -X POST https://tdx.transportdata.tw/auth/realms/TDXConnect/protocol/openid-connect/token \
  -d grant_type=client_credentials -d client_id="$TDX_CLIENT_ID" -d client_secret="$TDX_CLIENT_SECRET"
# 回傳 JSON 的 access_token
```

後端已有封裝：`api/tdx_adapter.py`。它會快取 token、到期前 60 秒自動換新、收到 401 時清掉 token 重取，並把逾時和連線錯誤轉成明確的錯誤碼。

### 1.3 TDX：6670 要用的端點

6670 在 TDX 歸類為**公路客運（InterCity）**，路線代碼 `THB6670`，子線 `THB6670A1`～`THB6670H2`。尾碼 1＝去程（往日月潭／埔里），2＝返程（往台中），與欄位 `Direction` 的 0／1 對應。

| 用途 | 端點 | 2026-10-25 實測 |
|---|---|---|
| 即時位置（A1） | `/api/basic/v2/Bus/RealTimeByFrequency/InterCity` | 20～22 台，每分鐘更新 |
| 所在站（A2） | `/api/basic/v2/Bus/RealTimeNearStop/InterCity` | 21～22 筆 |
| 預估到站（N1） | `/api/basic/v2/Bus/EstimatedTimeOfArrival/InterCity` | 846 筆，其中 124 筆有秒數 |
| 班表 | `/api/basic/v2/Bus/Schedule/InterCity` | 18 條子線但只有 84 筆時刻，不完整 |

```bash
curl -s --compressed -H "Authorization: Bearer $TOKEN" \
 "https://tdx.transportdata.tw/api/basic/v2/Bus/RealTimeByFrequency/InterCity?\$filter=startswith(RouteUID,'THB6670')&\$format=JSON"
```

**篩選的坑**

- 用 `startswith(RouteUID,'THB6670')` 最穩。
- 觀光專用端點 `/v2/Tourism/Bus/.../TaiwanTrip` 也能用，但它涵蓋全台好行路線，**而且沒有 `RouteName` 欄位**，用它篩選會回 HTTP 400。
- 免費會員短時間連續呼叫 5、6 次就會回 HTTP 429 `API rate limit exceeded`。輪詢建議 A1 每 60 秒一次、N1 每 120 秒一次，被擋就把間隔加倍。

### 1.4 好行官網 Bustime

- **站牌**（`6670_all_stops.json`）：以「路線名稱 → 去程／回程 → 站序」組織，座標放在 `PointInfo`，格式是 `"緯度,經度"`。拆欄位時注意順序：`[lng, lat] = [parts[1], parts[0]]`。欄位 `TdxId` 可對回 TDX 的 `StopID`。
- **線形**（`6670_linestring.json`）：Google 地圖疊圖格式，`overlays[0].path` 是一串 `{lat, lng}` 字串。「去程」只有 128 點，「回程」有 **2,133 點**，是精度最高的全線幾何。
- **TDX 代理**：官網提供 `POST https://beta.taiwantrip.tad.gov.tw/Bustime/GetTDX`，主體是 `source=Inter&type=Location&city=Other&routeId=6670`，回傳 `{isSuccess, data}`，其中 `data` 是 A1 格式的 JSON 字串。行控中心的「即時同步」按鈕就是呼叫這裡。**瀏覽器直接呼叫多半會被跨網域限制擋下**，正式使用要經過自己的後端。

### 1.5 存檔格式（`6670_bus_data/`）

| 檔案 | 內容 | 重點欄位 |
|---|---|---|
| `6670_realtime_bus_positions.json` | A1 快照，18 台車 | `PlateNumb`、`SubRouteName.Zh_tw`、`Direction`、`BusPosition.{PositionLon,PositionLat}`、`Speed`、`Azimuth`、`DutyStatus`、`GPSTime` |
| `6670_realtime_arrival.json` | N1 快照 | `StopName`、`EstimateTime`（秒）、`StopStatus`、`PlateNumb`、`StopSequence` |
| `6670_all_stops.json` | 站牌 | `StopName`、`StopOrder`、`PointInfo` |
| `6670_linestring.json` | 線形 | `回程.overlays[0].path`（2,133 點） |
| `6670_subroutes.json` | 子線清單 | `busNo`（6670A…）、`ptxUid`（THB6670） |

**欄位意義**（依 TDX 規格，以 Swagger 為準）：

- `DutyStatus`：0＝正常、1＝開始營運、2＝結束營運。快照中 18 台有 6 台是 2，**這些車不能當成在線**。
- `StopStatus`：0＝正常、1＝尚未發車、2＝交管不停靠、3＝末班已過、4＝今日未營運。
- `GPSTime`：該車最後一次回報時間。同一份快照裡，最舊和最新可能相差 90 分鐘，要逐車判斷是否逾時。

### 1.6 如何確認資料是真的

2026-10-25 的比對做法與結果：

- **重新呼叫 TDX A1**：快照欄位與即時 A1 完全一致，營運業者代碼相同（64），18 台中有 14 台車牌出現在當下的即時車隊。
- **路線形狀**：`route_coords.js` 的主線與 TDX 官方 `THB6670D1` 形狀相比，中位數誤差 1 m、P90 7 m。超過 300 m 的只有日月潭到向山那段，那是 F 線延駛段，D1 不經過。
- **檢查腳本**：在潭行3D 專案的 `scripts/occ_verify.py`、`scripts/tdx_probe.py`，詳見該專案的 `TDX_LIVE_HANDOFF.md`。

### 1.7 隱私與標示

- `PlateNumb` 是真實車牌。目前頁面會顯示車牌，GitHub Pages 是公開網站，要不要改成匿名編號（例如 `L01`）請團隊決定。
- 金鑰只能放在後端或本機腳本；前端頁面只讀已抓好的 JSON。

## 2. 怎麼做地圖

### 2.1 2D／3D GIS 地圖（`occ_dashboard.html`）

**技術選擇**：MapLibre GL JS 3.6.2，加上 CARTO **Positron** 淺色向量底圖（`basemaps.cartocdn.com/gl/positron-gl-style/style.json`）。

選它的理由：

- 開源、免金鑰。
- 支援 `pitch`（傾角）與 `bearing`（方位），一張向量底圖就能做出 3D 俯瞰。
- Marker 是一般 DOM 元素，車輛圖示、標籤、動畫都能用 CSS 做。

**初始視角**：

- 桌機：`center [120.78, 23.98]`、`zoom 10.4`、`pitch 55°`、`bearing 25°`，剛好把台中到日月潭整條走廊斜放進畫面。
- 手機：`zoom 9.7`、`pitch 45°`。

**路線圖層**（`drawRouteLines()`）：

1. **主線**：`REAL_6670_ROUTE_COORDS`。由 `6670_linestring.json` 的「回程」2,133 點轉成 `[lng, lat]`，取 5 位小數（約 1 m 精度），存在 `route_coords.js`。
2. **機場線**（6670E）：`ROUTE_6670E_AIRPORT_COORDS`，616 點，台中航空站經國道 3 號到高鐵台中站。原本只有少數節點，車會在兩點間來回跳動，加密到 616 點後才平順。
3. **每條線畫兩層**：
   - 底下是寬 8 px、半透明、模糊 3 的「光暈」層。
   - 上面是寬 3.2 px 的實線核心層。
   - 機場線核心改成虛線，與主線區分。

**站牌**（`renderStopsOnMap()`）：讀 `RAW_STOPS["6670 日月潭線"]["去程"]`，每站一個小圓點 Marker，點擊後跳出站序、站名、座標。

**視角按鈕**（`VIEW_PRESETS`）：全線鳥瞰、日月潭湖區、埔里、高鐵台中站，各有固定的 `center／zoom／pitch／bearing`，用 `flyTo` 平滑移動。

### 2.2 道路貼合（Map-Matching，`snapBusToRoute()`）

**問題**：GPS 有 10～50 m 漂移，直接畫會讓車浮在田裡或河上。

**做法**（點到折線的最近投影）：

1. 依子線選路線：`6670E` 用機場線，其餘用主線。
2. 對每一段線段 `a→b`，先用 ±0.015°（約 1.5 km）的外框快速排除遠的線段，再算投影：

   ```
   t = clamp( ((p−a)·(b−a)) / |b−a|², 0, 1 )
   投影點 = a + t·(b−a)
   ```

3. 取距離最小的線段，得到 `progress = 線段索引 + t`。這是車在路線上的位置，後面的推估都用它。
4. **距離超過 300 m 就放棄貼合**，回傳 `null`：這台車照原始 GPS 畫，而且不推估移動。原本沒有這個門檻，在場站或回場路上的車會被瞬移到路線起點。
5. **車頭方位**取所在線段的切線方向。經度差要先乘上 `cos(緯度)` 再算 `atan2`，否則在北緯 24° 會偏約 10%。往台中方向（`Direction=1`）把方向反過來。

### 2.3 位置推估（航位推算，`startFleetCruiser()`）

快照只有一個時間點；為了讓地圖不是靜止圖片，依回報車速沿路線往前推估。規則刻意保守：

| 規則 | 值 | 為什麼 |
|---|---|---|
| 速度倍率 | 1 倍 | 原本 2.5 倍會讓畫面位置很快偏離真實位置 |
| 最長推估 | 3 分鐘（`DR_MAX_SEC = 180`） | 超過就停在最後位置，跑馬燈提醒按「即時同步」 |
| 只推誰 | `DutyStatus ≠ 2`，且 `GPSTime` 與快照最新時間相差 ≤ 10 分鐘（`STALE_MIN`） | 已收班或訊號逾時的車不該動 |
| 到端點 | 停下並標「端點停等」 | 避免在終點來回震盪 |
| 標示 | 車號標籤後加「推估」；停止後改「最後回報 HH:MM」 | 讓看的人知道這不是 GPS |

推進方式：每一幀把 `車速(m/s) × 經過秒數` 換成距離，沿線段逐段扣掉。每段長度用 `Δlng × 102,000 m`、`Δlat × 110,900 m` 近似（北緯 24° 附近足夠）。

### 2.4 3D 地形沙盤（`3d_viewer.html`）

**產生方式**：Blender Python 腳本 `render_real_geo_corridor.py` 輸出 `6670_sunmoonlake_panorama.glb`（同時存一份 `.blend`），網頁用 Google `model-viewer` 3.4 顯示。

1. **座標轉換**：
   - 中心點 `(24.01°N, 120.76°E)`。
   - `x = (經度 − 120.76) × 101.4 × 2.2`
   - `y = (緯度 − 24.01) × 111.0 × 2.2`
   - 也就是把真實公里數放大 2.2 倍，讓走廊在畫面上夠寬。
2. **高程**：不是 DEM，而是分區階梯值：台中平原 0.25 → 草屯淺山 0.70 → 國道 6 號峽谷漸升 → 埔里盆地 2.10 → 日月潭 3.85。這是**示意地形**，要真實高程請改用內政部 20 m DEM。
3. **道路**：讀 `6670_linestring.json` 回程 2,133 點，每 5 點取 1 點（約 427 點）建成連續路面與中線。
4. **車輛**：讀 `6670_realtime_bus_positions.json`，把 18 台車的 GPS 轉成模型座標放上去。**模型匯出後車輛是固定的**，網頁上不會動。
5. **網頁上的熱點與「沙盤對焦」**：依每台車的實際 GPS 判斷區域（國道 6 號、埔里、水社、向山、台中、高鐵），標籤顯示該區車數，點擊列出車輛。原本寫死車號與車速，已改成依資料產生。

**限制**：沙盤是靜態模型，要看車輛移動請用行控中心。要讓沙盤的車也動，可以用 `geo_to_3d()` 把即時 GPS 換成模型座標，再用 model-viewer 的 hotspot 動態更新位置。

## 3. 行控中心怎麼設計

### 3.1 設計想法

行控中心是給**調度員盯一整班**用的，不是簡報頁。設計問題只有三個：

| 問題 | 放在哪 | 怎麼回答 |
|---|---|---|
| 車在哪？ | 中央地圖 | 貼線後的車輛圖示，顏色分速度 |
| 哪台車有狀況？ | 左側車隊清單 | 每台一張卡：車號、子線、方向、狀態、車速 |
| 乘客要等多久？ | 右側 ETA | 依車：下一站倒數；依站：每站最近一班 |

版面因此是「**地圖滿版＋左右兩個浮動面板＋上方指標列＋下方視角列與跑馬燈**」。地圖永遠是主角，面板可以收合（桌機）或改成底部抽屜（手機）。

### 3.2 版面與尺寸

**桌機**：

- 上方標題列 70 px：品牌、4 個指標、4 個功能鈕（3D 沙盤、3D 巡航、即時同步、音效）。
- 左右面板各 370 px 寬，距頂 86 px、距底 64 px。邊上有收合鈕。
- 下方 64 px：視角按鈕與跑馬燈。跑馬燈固定顯示「資料時間」與推估規則。

**手機（≤ 768 px）**：

- 頁面固定不捲動：`body` 用 `position: fixed` 與 `100dvh`。否則手機瀏覽器的網址列會把標題列推出畫面。
- 標題列 56 px：只留圖示按鈕，標題單行加省略號，隱藏音效鈕，加上 `env(safe-area-inset-*)` 避開瀏海與底部橫條。
- 面板改成底部半高抽屜（最高 58 dvh），由底部導覽列切換：3D 地圖、車隊遙測、到站監控。
- 抽屜裡的標題與子線分頁設 `flex-shrink: 0`，抽屜變矮時才不會被壓扁。
- 地圖縮小（手機 zoom < 12.5、桌機 < 11.2）時隱藏車號標籤，避免互相重疊；被選取的車仍顯示。

### 3.3 視覺語言（白色主題）

| 用途 | 顏色 |
|---|---|
| 底色／面板 | `#f1f5f9` ／ 白 92% 透明 |
| 主色（路線、選取） | 深藍 `#0284c7` |
| 正常／行駛中 | 綠 `#059669` |
| 停等／警示 | 琥珀 `#d97706` |
| 高速（>80 km/h）／下一站 | 玫瑰紅 `#e11d48` |
| 次要文字 | `#64748b` |
| 已收班／逾時 | 半透明 45% |

- 顏色都定義在 `:root` 的 CSS 變數。改色時改變數，不要改個別元件。
- 車速分三級：0–30 低速（藍框）、30–80 中速（綠框）、>80 高速（紅框）。
- 白底配深藍主線加淡藍光暈，對比足夠，投影或白天戶外也看得清楚。

### 3.4 互動設計

| 動作 | 結果 | 細節 |
|---|---|---|
| 點車輛（地圖或清單） | 飛到該車並跳出遙測彈窗 | 一次只留一個彈窗；抵達後才鎖定跟隨，避免鏡頭跟隨打斷飛行；右側 ETA 同步切到這台 |
| 彈窗「3D 鏡頭跟隨」 | 鏡頭跟著車移動並慢慢環繞 | 每幀 `jumpTo` 對準車輛目前位置、方位 +0.1°；拖曳地圖即解除 |
| 3D 巡航 | 8 個停留點自動輪播 | 說明文字即時列出該點 3 公里內的車，不寫死 |
| 子線分頁 | 只顯示該子線的車與卡片 | 完全比對（`6670D` 不會誤中其他代碼）；同步後保留目前篩選 |
| 即時同步 | 重新抓 A1 | 成功就更新資料、下拉選單、ETA、篩選；失敗就照實顯示原因與目前快照時間 |
| 網址參數 | `?focus=車號` 直接鎖定該車；`?tour=1` 直接開始巡航 | 從 3D 沙盤跳過來時使用 |

### 3.5 狀態判斷（`busState()`）

所有面板共用同一個函式，避免各處說法不一致：

```
DutyStatus = 2                       → 「已結束營運」（不推估、半透明）
快照最新時間 − GPSTime > 10 分鐘      → 「訊號逾時（HH:MM）」（不推估、半透明）
其他：Speed > 0                       → 「行駛中」
      Speed = 0                       → 「停等中」
```

## 4. 儀表板（指標）怎麼設計

### 4.1 原則

每個數字都要能回答「從哪來、怎麼算、什麼時候的」。做不到的數字就標「示意」，或乾脆不放。

### 4.2 指標定義

| 位置 | 指標 | 算法 | 來源 |
|---|---|---|---|
| 上方 | 在線營運車輛 | `busState().live` 的車數／總車數（例：12／18） | A1 快照 |
| 上方 | 行駛中平均車速 | 營運中且 `Speed > 0` 的車，取平均 | A1 快照 |
| 上方 | 主線站點總數 | `RAW_STOPS` 去程站數（31） | 好行官網 |
| 上方 | 日月潭蓄水率 | **示意值**，未串接 | 無 |
| 右側 | 國道六號（車隊平均） | 位於 北緯 23.97–24.04°、東經 120.69–120.93° 且行駛中的車，平均車速與車數 | A1 快照 |
| 右側 | 台21線（車隊平均） | 北緯 < 23.97°、東經 > 120.88° 且行駛中的車 | A1 快照 |
| 右側 | 日月潭水位、水社氣溫 | **示意值**，未串接 | 無 |
| 右側 | 下一站倒數 | 該車在 N1 的第一筆：分鐘＋秒 | N1 快照 |
| 下方跑馬燈 | 資料時間 | 快照中最新的 `GPSTime` | A1 快照 |

**路況為什麼用車隊平均**：本來寫死「暢通 92 km/h」，沒有來源。改用自家公車的回報車速，至少是真實量測；樣本少時一併顯示車數，讓看的人自己判斷。

### 4.3 ETA 面板

- **依指定公車**：上方摘要卡顯示車號、子線、方向、狀態、下一站與倒數；下方時間軸列出該車後續各站的分鐘數，下一站以紅色強調。沒有 N1 資料時，依狀態顯示「已結束營運」或「此車目前沒有到站預估資料」，不再假裝「即將啟程」。
- **依全線站牌**：列出 31 站，每站顯示最近一班的車號與分鐘數；2 分鐘內以紅色強調。
- **點任何一個站牌列（兩種模式都可以）**：地圖切到**全線鳥瞰**（正北朝上、不傾斜），用紅色脈動標記標出該站，標籤顯示站名與最近一班。
  - 用 `cameraForBounds` 把整條路線和該站一起放進畫面，並扣掉左右面板、上下列的遮擋（桌機面板展開時左右各留 420 px）。
  - 抵達後檢查標籤有沒有被面板蓋住，被蓋住就往左或往右偏移。
  - 手機會自動收起抽屜，讓地圖露出來。
  - 點紅色標記可放大到站牌（zoom 15.5）。
  - 站牌座標優先用好行官網 `PointInfo`；官網清單沒有的站（ETA 裡有 25 個站名不在官網清單），改用 `route_coords.js` 的 `TDX_STOP_GEO`。這份資料是 TDX StopOfRoute 的全子線站牌座標（114 站，2026-10-25 擷取），涵蓋全部 47 個 ETA 站名。「榮民診所」與「榮民醫院」視為同一站。

### 4.4 入口頁（`index.html`）

兩張卡片分別進 3D 沙盤與行控中心。頁首標示「TDX 車輛動態快照 2026-10-25 13:35」，下方指標同樣標「快照」或「示意」，不寫「實時串流中」。

## 5. 修改與發布流程

```bash
# 1. 改根目錄的檔案（occ_dashboard.html / route_coords.js / 3d_viewer.html / index.html）
# 2. 同步到 public/（GitHub Pages 從這裡發布）

git add occ_dashboard.html 3d_viewer.html index.html route_coords.js public/
git commit -m "說明這次改了什麼"
git push origin master
```

`_backup_*/` 已加入 `.gitignore`。

**發布前檢查清單**：

- [ ] 跑馬燈上的「資料時間」與資料檔一致。

## 6. 已知限制與下一步

| 項目 | 現況 | 建議 |
|---|---|---|
| 即時性 | 頁面內嵌的是 2026-10-25 12:05–13:35 的快照 | 架一個本機或雲端代理：後端持有 TDX 金鑰，每 60 秒抓 A1、每 120 秒抓 N1，前端定時讀 `/live.json` |
| 瀏覽器同步 | 直接呼叫官網代理多半被跨網域限制擋下 | 同上，改走自己的後端 |
| 機場線銜接 | 6670E 往日月潭的車推估到高鐵就停 | 把機場線與主線串成同一條，或依子線建立完整線形 |
| 3D 沙盤 | 靜態模型；高程是分區示意 | 改用 DEM；車輛改用動態 hotspot |
| 車牌 | 公開顯示 | 視需要改匿名編號 |
| 無 WebGL 環境 | 建立地圖時出錯，整頁停擺 | 用 try/catch 包住 `new maplibregl.Map`，失敗時至少顯示車隊與 ETA 面板 |
| 示意數值 | 水位、氣溫、蓄水率 | 串接水利署與氣象署開放資料，或移除 |
