# 潭行 6670 班表情境工作台

2026-10-23 從使用者提供的「潭行3D」原型整合。原始資料夾未修改。主站入口為「班表情境」，完整方法在「模型方法」頁，部署輸出為 `/scenario-lab/index.html`。

## 採納內容

- 淡色地形與等高線、三維公車、車站設施；選取車輛只開啟平面位置圖，不強迫移動鏡頭，跟隨模式另行開啟。
- 6670 公開班表和 TDX 線形快照、按方向的票證需求、時段熱圖與 OD 聚合。
- 需求回歸、同星期基準、情境班次配置與全天模擬比較；六個面板共用同一個 LIVE.sim。
- 內部營運小幫手將經驗證的數值模擬快照送至同源後端，由 OpenRouter 的 `deepseek/deepseek-v4.1-flash-1017` 整理答案。金鑰只留後端；失敗時明示規則式降級。

## 修正而非直接照搬

1. 假日以本地日曆日期計算，避免 UTC 轉換偏移一天。2026 假日仍是待核對假設。
2. 回測改為逐日 expanding window：兩模型都只用預測日前資料，MAE 分母只計有效配對日。
3. 保留低量日；MAD 近零時保護除法；區間下限截零。殘差帶標為未校準，不宣稱預測涵蓋率。
4. 歷史擬合和未來外推分開說明；默認 2025-11-01 是歷史需求情境，不是 GPS 回放。
5. 建議發車限制在現行首末班時間內；車隊限制仍無法滿足時禁止套用。現行服務底線只是時段班數，並不保證每個 OD 服務。
6. 實際模擬和車輛串接統一至少 10 分鐘端點整備；壅塞速度下降 40% 對應時間乘 1/0.6。
7. 需求生成使用現行班表固定 OD 時窗，與行車亂數分離。相同種子生成相同旅客，不因候選方案減班而刪掉需求。
8. 乘客公里在每個上下車站前後分段累加；增加期末候車／在車與生成量指標，便於核對守恆。
9. 票價改標「實扣中位數」、需求改為刷卡筆數。OD n≥10，沒有卡號、車牌或逐筆交易。
10. 小幫手固定營運模式與主題限制，旅遊／票價不回答。正常狀態由後端 LLM 解讀核准資料與畫面快照；降級時才使用本機規則。回答標示來源與模擬時間，不能當真實 GPS。

## 未採納的主張

- 貪婪串接不保證最少車輛，減班啟發式沒有成本金額目標，故稱「班次情境建議」。最低成本仍使用主站原求解器；結果僅對其示範候選集合成立。
- 程序地形不是 DEM；A 線借用 D 線形、F 向山延伸與九族投影是近似，不能當作真實道路重建。
- 票證重建車次／在車量不是實測車隊與完整客流。官網主班表不含完整加班及九人座，可能低估供給。
- 碳排因子是固定情境參數，與主站另一組參數不同，不直接跨頁比較或作正式 ESG 宣稱。

## 檔案和建置

`src/a_geo.js` 座標與線形；`b_scene.js` 場景；`c_models.js` 設施模型；`d_sim.js` 狀態與旅客模擬；`e_forecast.js` 回歸與回測；`f_opt.js` 班次啟發式；`g_ui.js` 面板、模擬快照與助理 API 介接。`parts/` 為繪圖部件。

`data/ops-aggregates.json` 是原型從主專案兩年度票證 XLSX 產出的聚合快照；`route-6670.json` 和 `timetable-6670.json` 是原型從主專案既有公開快照轉出的精簡格式。保留檔內 generated_at、來源和方法欄位。原始 XLSX 不發布。資料更新需重新執行原型的資料匯出腳本並檢查口徑，不可把逐筆交易直接替換聚合。

- `python3 scenario-lab/build.py public/scenario-lab/index.html` 更新靜態頁。
- `npm run build` 自動執行上述步驟，再建置主站。不要直接修改生成的 HTML。
- `TZ=Asia/Taipei npx vitest run scenario-lab/model.test.js` 驗證日期、回測、服務時窗、不可行判定、旅客守恆、共同需求、整備與資料欄位。
- 使用 Three.js 0.160.0 CDN 與 Google Fonts；首開需網路。主站套件中的 Three.js 版本獨立。

這個工作台以 iframe 隔離原型全域變數及 Three.js 版本。與原有「數位孿生」設定不互通，不能把兩頁 KPI 當成相同情境。後續如需同一全域情境，先抽離純模型 API 再移植 React，避免兩個引擎互相覆寫。

## 模擬邊界

旅客只在現行班表 OD 首班前 20 分至末班前 5 分生成；時窗外需求被排除，總生成量不等於日刷卡總量。Poisson 大 λ 使用近似。服務先到先上，車容量 43，停站 0.4+0.05×上下車人數分鐘（起站除外），每 5 分鐘移除已等待超過 90 分鐘者。平均／最長等待只統計已上車者，必須搭配流失、期末排隊共同解讀。

路段距離以平面線形 ×1.08 近似，空車調度距離含保守調度時間折算，並非里程表。車公里／排放只是情境比較。回歸使用完整年度的固定時段分布生成情境，因此歷史回放不是事前預測實驗；嚴格時間隔離只適用獨立的逐日總量回測。

## 方法頁直達入口

`?panel=ops|fc|pk|viz|opt|bot` 可開啟指定分頁，優先於瀏覽器上次分頁。只接受這六個值；未知值退回原有有效分頁或模擬營運。方法頁按鈕直接帶入對應入口，不需要猜哪個分頁使用該公式。
